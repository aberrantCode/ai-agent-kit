Vendor-Neutral Classification

Decision filter: asset placement by vendor contract surface

The Test
Core Question
Does this asset need vendor frontmatter, tool syntax, or an install-path convention to function?
Scope
An asset qualifies for shared/ only if it contains no vendor-specific frontmatter contract, tool syntax, or install-path convention — plain markdown/config any vendor's agent can consume.
two outcomes
✓ YES
Has vendor contract surface
Belongs in vendor-specific tree
claude/ Claude skills, instructions, commands
codex/ Codex CLI extensions
gemini/ Gemini CLI extensions
✗ NO
Vendor-neutral asset
Belongs in shared/<class>/
prompts/ Reusable standalone prompts
workflows/ Vendor-neutral orchestration docs
configs/ Reusable config fragments
plugins/ External plugin reference lists
Implementation Guideline
New Asset, New Class
When adding an asset to a new shared/<class>/ directory for the first time: create the directory with a README.md first, describing purpose, conventions, and this vendor-neutral test. Only after does content get added.
