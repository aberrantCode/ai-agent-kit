Git Hook Sequences

Two hooks, two clients, one push · flow diagrams

The Setup · two independent hooks
git-push-opens-Zed hook is a Claude Code client-side PreToolUse hook living in ~/.claude/settings.json — fires ONLY inside Claude Code, BEFORE the tool call executes. pre-push git hook is installed by install-hooks.ps1, lives in scripts/git-hooks/, and fires for EVERY push FROM ANY CLIENT once core.hooksPath is configured. They are independent, they run in sequence, and they validate different concerns.
Scenario 1: push from Claude Code (with Zed review)
Sequence · Claude Code push
What happens when you run git push from Claude Code:
Developer / Claude Code
  • 1. Initiate · git push tool call
  • BEFORE Claude Code's tool executes…
  • 2. Pre-Tool Hook fires · git-push-opens-Zed (client-side)
  • 3. Opens Zed · human reviews diff
  • 4. Human approves · close Zed
Claude Code (tool executor)
  • 2. Hook runs · ~/.claude/settings.json PreToolUse
  • 3. Zed opens for diff review
  • 4. Detects close · continues
  • 5. Executes · git push → invokes git
git (git-side)
  • 5. Receives · push request
  • 6. Fires · pre-push git hook
  • 7. Runs · validate.ps1
  • 8. Validates · checks exit code
  • ✓ PASS → push proceeds
  • ✗ FAIL → push aborts
Key insight: The Zed review (step 2–4) is a preview gate for the developer; the validate.ps1 check (step 6–8) is an enforcement gate that runs regardless of whether Zed was opened. If Zed approved but validate fails, the push still aborts.
Scenario 2: push from bare terminal (simpler — no Zed)
Sequence · Bare terminal push
What happens when you run git push from a terminal (not Claude Code):
Developer (terminal)
  • 1. Run · git push in terminal
  • 2. Wait · git-side validation
  • ✓ Success → push completes
  • ✗ Failure → aborted, error shown
git (git-side)
  • 1. Receives · push request
  • 2. Fires · pre-push git hook
  • 3. Runs · validate.ps1
  • 4. Validates · checks exit code
  • ✓ PASS → push proceeds
  • ✗ FAIL → git aborts, stderr returned
Note
  • No Zed review · client-side hook doesn't exist outside Claude Code
  • Zed hook is Claude-only: defined in ~/.claude/settings.json PreToolUse, applies only to Claude Code tool invocations
  • git hook is universal: defined via core.hooksPath in git config, applies to every git push from any client
Hook Scope · Client-side vs. Git-side
git-push-opens-Zed
Client: Claude Code only
Defined: ~/.claude/settings.json PreToolUse
Trigger: Before Claude Code's git push tool call
Purpose: Human diff review
pre-push
Client: Any (terminal, Claude Code, VS Code, git CLI)
Defined: scripts/git-hooks/ via core.hooksPath
Trigger: git push from anywhere
Purpose: Automated validation
Independence
Hooks don't coordinate. Zed is optional preview; validate.ps1 is mandatory enforcement. Either can block; both must pass when both exist.
Failure Modes · What stops a push
  • Zed review denied: Developer closes Zed without approving. Claude Code detects close and continues (does not re-open). Still proceeds to git.
  • validate.ps1 fails: Hook detects violation. git command exits non-zero. Push is ABORTED by git itself, regardless of Zed outcome.
  • Both fail: Zed was skipped/ignored AND validate found issues. Zed review is pre-commit feedback; validate is the final gate.
Installation & Configuration
git-push-opens-Zed (Claude Code)
File: ~/.claude/settings.json
Hook type: PreToolUse
Scope: client-side, Claude Code only
Run condition: before Claude Code's own git push tool call
pre-push (git)
File: scripts/git-hooks/pre-push
Config: core.hooksPath = scripts/git-hooks
Run condition: every git push, from any client
Install: pwsh scripts/install-hooks.ps1 (optional; idempotent)
