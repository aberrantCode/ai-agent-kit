Agent-Orchestrator Handoff

task lifecycle · plan → task → execution → completion → reconciliation

Coordination Model
The orchestrator and agent communicate through files, not directly. The plan file is the orchestrator's source of truth; task files are the agent's workspace. Completion is signaled via a sentinel block appended to the task file. Reconciliation happens when the orchestrator reads the sentinel.
Orchestrator
1
Create / Update Plan File
Creates or updates docs/plans/<slug>-plan.md with tasks table: # | Task | Covers CAP-ID | Role | Status | Notes. Each row starts with Status=todo.
3
Run /continue-tasks
Command picks up a todo row from the plan. Creates a corresponding task file in docs/tasks/active/.
6
Read Completion Sentinel
Watches for ## Completion block appended to the task file by the agent. When observed, proceeds to reconciliation.
7
Reconcile & Archive
Updates the plan file's Status column to done. Moves task file from docs/tasks/active/ to docs/tasks/archive/.
Agent
2
Claim Task
Agent sees the task file in docs/tasks/active/. Updates status to in-progress. Role (from plan) determines which agent type: planner, tdd-guide, code-reviewer, security-reviewer, build-error-resolver, e2e-runner, doc-updater, refactor-cleaner, or general-purpose.
4
Execute Work
Performs the work specified in the task file. Works only in docs/tasks/active/ — does NOT edit the plan file. Commits changes and updates task file as needed.
5
Append Completion Block
When work is done, appends ## Completion block to the task file. This is the completion sentinel that signals to the orchestrator: work finished, ready for reconciliation.
8
Next Task
Orchestrator's reconciliation triggers removal of the task file. Agent loop repeats: picks next todo task and begins execution cycle again.
Status Vocabulary
todo — eligible for pickup
in-progress — task file exists in active/
done — completion sentinel observed, archived
blocked — blocker issue written, no auto-retry

Key Principles
  • → Plan file is orchestrator-owned. Only the orchestrator updates plan Status. Agents never edit it.
  • → Task files are agent-owned. Agents work within docs/tasks/active/, appending completion blocks when done.
  • → Completion is file-based. The ## Completion block is the signal, not a direct API call.
  • → Reconciliation is automatic. Orchestrator reads the sentinel, updates the plan, and archives the task file.
