Commit Scope Decision

classify staged files in a chore-lane commit

Decision Authority

For a chore-lane commit, classify each staged source file against two glob lists: product_scope and chore_safe. Behaviour-bearing code cannot ride the lightweight chore lane. Route unconfirmed files through /groom → /add-feature instead.

Manifest Definitions
product_scope
Behaviour-bearing source code that defines feature implementation. Examples: src/**, api/**, components/**, app/**, packages/*/src/**
chore_safe
Safe-by-definition files: documentation, scripts, CI config, generic config. Examples: docs/**, scripts/**, .github/**, *.md, *.config.*
Classification Flow
📋 For each staged file, check: Does it match product_scope OR chore_safe OR neither?
🚫 HARD FAIL
Matches: product_scope
Behaviour-bearing code cannot ride the chore lane, regardless of scope_confirmed flag. Route through /groom → /add-feature to create a proper spec + plan instead.
✓ ALLOWED
Matches: chore_safe
Docs, scripts, CI config, and generic config files are safe by definition. Proceed with commit.
⚠️ CONDITIONAL
Matches: Neither list
Allowed only if the authorizing chore task has scope_confirmed: true. Operator explicitly acknowledged the file is out-of-manifest but safe.
Reject · no override possible
Accept · always safe
Accept · requires confirmation
Rules & Fallback
Manifest missing? If the product_scope or chore_safe file is missing, the chore lane is inert — the guard fails closed for every chore task until the manifest exists. This ensures no accidental product code lands in the chore lane due to misconfiguration.
Key Point: scope_confirmed can unblock an unclassified file; it can NEVER override a product_scope hit.
