Vendor Mirror Flow

ai-agent-kit skill distribution across Claude, Codex, and Gemini CLIs

Core Principle
Skills flow strictly one direction: claude → codex → gemini. Never the reverse. Each vendor carries a source-version stamp referencing the Claude skill/version it was mirrored from.
Vendor Mirror Architecture
claude/
Canonical authoring surface. Everything is authored here first. Source of truth for all skills.
codex/
On-demand mirror. Created manually, only when a skill is actually used from Codex—never auto-generated from every Claude skill.
gemini/
Frozen mirror. Frozen at its current set of skills. New Claude skills are NOT automatically mirrored here.
/audit-skills
Detects gaps and staleness across mirrors. Compares source-version stamps against current Claude originals. Reports informational only—never as failure.

Operational Principles
  • One-way mirror flow: claude → codex/gemini. Never reverse or sideways.
  • Codex mirrors are on-demand: Created only when a skill is actually used from Codex—no auto-generation from every Claude skill.
  • Gemini mirrors are frozen: New Claude skills do NOT auto-mirror. Growing the Gemini set is a deliberate, manual decision.
  • Source-version stamps: Each mirror carries metadata referencing the Claude skill/version it was mirrored from.
  • Audit is informational: The /audit-skills command reports staleness and gaps—informational only, never as a failure gate.
