Spawn Terminal

generic wt-launch core · tab color · env injection · verified launch

Entry · exactly one run mode
Every call to scripts/spawn-terminal.ps1 resolves what the new tab runs from exactly one of two mutually exclusive inputs — never hand-write a raw wt command, since a space in a title makes wt treat the rest of the line as a command.
-Command '<line>'
An inline command, e.g. 'npm run dev' or 'git log --oneline'.
-ScriptPath '<path.ps1>'
Run a prepared script (+ optional -ScriptArgs) — the path a higher-level launcher uses to inject a runner it built itself.

Options that matter
  • -WorkingDirectory
    Where the tab starts
    Main checkout, worktree, or unrelated folder. Defaults to the current location.
  • tab color
    Auto-resolved per repo, unless overridden
    Omit -TabColor and the script resolves one stable color per repo from ~/.claude/repo-colors.json, keyed by origin remote (shared across worktrees). -TabColor '#RRGGBB' overrides for one launch, -ColorScheme '<name>' also recolors the palette, -NoColor skips resolution. Resolution never blocks a launch — failure just means an uncolored tab.
  • window mode
    -Fullscreen / -Maximized / -Focus
    Windows Terminal global flags. Long-form used deliberately — short aliases differ between WT versions.
  • -CloseOnExit
    vs. default -NoExit
    By default the tab stays open after the command finishes so you can read its output. Pass for fire-and-forget commands.
  • -SetEnv
    Environment injection
    A spawned tab inherits nothing from the launching shell. "KEY=VALUE" adds a var, bare "KEY=" drops one set earlier. No default environment — tool-specific launchers layer their own on top.
  • -VerifyProcess
    Confirm the launch actually came up
    Poll for a new process of that name and report a confirmed PID. Guards against the invisible failure mode: a tab that opens and dies immediately.
  • -DryRun
    Preview without launching
    Writes the runner script and prints it — worth doing after changing environment or command to see exactly what the tab will execute.
Launch Path · fallback chain
1 · Windows Terminal (wt)
Preferred path when wt is on PATH — ships with Windows 11.
2 · Plain pwsh console
wt can be absent on stripped-down or server installs — falls back automatically.
3 · Report the runner path
If even a plain console fails, the script reports the runner-script path so the caller can run it themselves.
Design Principles
  • Everything runs through one script — never hand-write a wt invocation.
  • <skill-dir> is this bundle's own directory, not the receiving repo's root.
  • Verify from the script's printed output (PID or launch note), not from the call merely returning.
  • This is the generic terminal-launch core — no Claude-specific or tool-specific logic lives here.
  • session-handoff:handoff builds its Claude-session launcher on top of this skill, not beside it.
